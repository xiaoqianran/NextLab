接口

POSThttps://api.openai-next.com/v1/chat/completions

Authorization: Bearer $OPENAI_NEXT_API_KEY · Content-Type: application/json

api.openai-next.com 和 draw.openai-next.com 的 API Key 互不通用，用错站点返回 401。

参数

改一个值，右边的请求就跟着变。

prompt*string

消息 · 要问模型的话。同一条消息可以发给多个模型对比。

≤ 32,000 chars

imagesimage url[]

图片 · 和消息一起发给模型看的图片（最多8张）。

≤ 8 items

systemstring

系统提示词 · 放在对话最前面的指令：角色、语气、格式要求。

≤ 8,000 chars

temperaturenumber

温度 · 越高越发散，越低越稳定；不填用模型默认值。

0–2 step 0.1

自动

max_tokensinteger

最多输出token · 回答最长多少token；也决定花费上限。

1–128000

streamboolean

流式输出 · 边生成边显示（服务端发送事件）。

默认 true

top_pnumber

Top P（核采样） · 只从累计概率前P的词里选；和温度一般只调一个。

0–1 step 0.05

自动

frequency_penaltynumber

频率惩罚 · 正值让模型少重复已经说过很多次的词。

-2–2 step 0.1

自动

presence_penaltynumber

存在惩罚 · 正值鼓励模型谈到新的内容。

-2–2 step 0.1

自动

seedinteger

随机种子 · 相同种子和参数尽量给出相同的回答（不保证）；不填为随机。

0–2147483647

stopstring[]

停止词 · 每行一个，生成到其中任何一个就停（最多4个）。

≤ 1,000 chars

response_formatenum

输出格式 · JSON对象：回答一定是合法JSON（提示词里要提到JSON）。要指定JSON Schema，用「原始请求体」覆盖response_format。

reasoning_effortenum

思考强度 · 推理模型回答前想多久：越高越准、越慢越贵。

minimal · low · medium · high · xhigh

logprobsboolean

返回概率 · 回答里附上每个token的对数概率。不是每个模型都给（2026-10-13实测DeepSeek、GLM会给，其他收下但不返回）。

top_logprobsinteger

候选概率数 · 每个位置再列出最可能的几个候选token（要开「返回概率」）。

0–20

自动

parallel_tool_callsboolean

并行调用工具 · 允许一次回答里调用多个工具（带工具时才有意义）。

OpenAI兼容接口：同一个 /v1/chat/completions能调用平台上所有对话模型，按输入和输出token计费。

stream: true时以服务端发送事件（text/event-stream）逐段返回，每行data: 是一个JSON片段，最后是data: [DONE]；加stream_options.include_usage会在最后一段带上token用量。

OpenAI较新的模型用max_completion_tokens而不是max_tokens。

支持（已实测）
system
content — 放在最前面的指令：角色、语气、格式。
user
content — 用户说的话；能看图的模型可以是文字加图片的数组。
assistant
content, tool_calls — 模型之前的回答，原样放回去；只调用工具的回合content为null，带tool_calls。
tool
tool_call_id, content — 一次工具调用的结果，tool_call_id对应assistant消息里那次调用的id；每个调用一条。

接口不记得之前的对话：每次请求都要带上完整的messages（最早的在前），模型的回答要作为assistant消息放回去。

整段对话每次都按输入token计费，越往后单次越贵；超过上下文窗口会被拒绝，需要删掉最早的回合（NextLabs会整回合删除，不会把工具结果和它的调用拆开）。

工具调用：在tools里声明函数；回答里出现tool_calls（finish_reason为tool_calls）时，执行每个调用，把这条assistant消息和每个调用的tool消息追加到messages，再请求一次。流式时tool_calls按index分段到达，arguments需要拼接。

推理模型返回的reasoning_content不要放回messages。

看图：能看图的模型（vision）里，user消息的content可以是数组：{type:"text"}加若干 {type:"image_url", image_url:{url}}，url可以是公网地址或data URL。图片每轮都会随历史再发一次、按输入计费。
